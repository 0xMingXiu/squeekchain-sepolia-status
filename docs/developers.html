TL;DRLink to this section

  • SqueekCore V3, SqueekMining version 6, SqueekToken and SqueekNFT form one contract graph, deployed on the Sepolia testnet.
  • Every contract has a function-by-function page and a published ABI; addresses and identities are in one deployment record.
  • Verify the graph before trusting any read, and follow the integration invariants below.

OverviewLink to this section

Squeekchain's contracts record the hamster's settled work, issue SQK for completed Squeek blocks, and track the Squeeks that share it. Everything an integration needs is onchain: there is no SDK, and the public API reference is coming soon.

Where to start

  • First read: Quickstart verifies the deployment and reads SqueekCore in three files.
  • Working with a coding agent: Build with AI installs the squeekchain agent skill with npx skills add https://docs.squeekchain.com.
  • Wallets, marketplaces and agents acting for owners: Build owner actions prepares claims and merges for the owner's wallet to sign.
  • Indexers and analytics: Index events builds a projection that survives reorgs.
  • Exact ABI-level detail: the contract pages for SqueekCore, SqueekMining, SqueekToken, SqueekNFT and the DotGrid renderer.

Integration invariantsLink to this section

  1. Verify before reading. Check chain ID, proxy implementation, runtime hash, layout digest, implementation version, governance owner, launch configuration and the links between the four contracts. See Verify the deployment.
  2. One block per snapshot. Read everything at one Ethereum block and keep its hash.
  3. Use bigint. viem returns bigint for uint64 and wider; never convert cumulative totals to number.
  4. Count blocks from block units. Height is cumulativeBlockUnits / 1_000_000_000. Never divide physical work by difficulty.
  5. Price with the previous difficulty. An event's difficulty prices the next active round, not its own.
  6. Respect the certified frontier. Rounds after settledThroughRound are unknown, not zero. Every BatchSettled advances the frontier, including zero-work batches.
  7. Read ownership live. Read ownerOf immediately before an owner action. Approved operators cannot claim or merge.
  8. Prepare, don't sign. Claims and merges are signed by the NFT owner's wallet. Simulate every call and hand over unsigned calls; never hold or request a private key.
  9. Count supply once. CheckpointMinted and the mint Transfer describe the same SQK.
  10. Roll back on reorgs. Key events by (chainId, blockHash, transactionHash, logIndex) and replay derived state from the common ancestor.
  11. Treat metadata as untrusted. Never inject a tokenURI SVG into application markup.
